Documentation

Learn how to connect WatchTower to your projects and start tracking errors in real time.

Getting started

01

Create an account and register your app

Sign up for a WatchTower account and log in. Navigate to the App Selection page and register the app you want to monitor with a name and optionally a URL for uptime monitoring. WatchTower automatically polls your app's URL every 5 minutes and will alert you by email if it goes down.

Once registered, WatchTower generates a unique API key for your app. Copy it — you will need it in the next step.

02

Add collector.js to your project

The WatchTower collector is a single JavaScript file you drop into any web app. It automatically tracks:

  • JavaScript errors — unhandled exceptions and promise rejections with severity classification
  • Page performance — load time, DOM content loaded time, TTFB, and JS memory usage
  • API latency — intercepts all fetch() calls and records how long each one takes
Download collector.js
03

Add the script tag to your HTML

Place collector.js somewhere your HTML can reach, then add the following script tag to the <head> or near the end of the <body> of each page you want to monitor: 

<script
    id="collector-script"
    src="/scripts/collector.js"
    data-apikey="YOUR_API_KEY"
    data-release="1.0.0">
  </script>
Attribute Description
data-apikey The API key generated by WatchTower when you registered your app
data-release A version string for this deployment (e.g. "1.0.0" or a git SHA) — used to correlate errors to a specific release

No build step or package install required. Once the script is on the page, all errors and performance data are sent to WatchTower automatically.

Advanced Sending events manually via the API

If collector.js doesn't fit your stack, you can POST events directly to the WatchTower API from any environment — a Node.js server, a CI pipeline, or a non-browser client. Authentication is done by including your app's apiKey in the request body (no session cookie needed).

Report an error

POST /api/events/error

FieldRequiredDescription
apiKeyYesYour app's API key from the App Selection page
messageYesError message text
stackNoStack trace string
errorTypeNoe.g. "TypeError", "RangeError"
severityNo"low" | "medium" | "high" | "critical"
urlNoPage or route where the error occurred
releaseNoVersion string or git SHA to tie the event to a release
timestampNoISO 8601 string — defaults to server time if omitted
 
fetch("https://your-watchtower-host.com/api/events/error", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    apiKey:    "YOUR_API_KEY",
    message:   "Uncaught TypeError: Cannot read properties of null",
    stack:     error.stack,
    errorType: "TypeError",
    severity:  "high",
    url:       "/dashboard",
    release:   "1.0.0"
  })
});

Report a performance metric

POST /api/events/performance

FieldRequiredDescription
apiKeyYesYour app's API key from the App Selection page
loadTimeMsNoFull page load time in milliseconds
domContentLoadedMsNoTime until DOM content loaded (ms)
ttfbMsNoTime to first byte (ms)
apiEndpointNoThe API route being measured
apiLatencyMsNoRound-trip time for an API call (ms)
memoryMBNoJS heap usage in MB
urlNoPage or route being measured
releaseNoVersion string or git SHA
timestampNoISO 8601 string — defaults to server time if omitted
 
fetch("https://your-watchtower-host.com/api/events/performance", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    apiKey:       "YOUR_API_KEY",
    loadTimeMs:   1240,
    ttfbMs:       180,
    memoryMB:     42.3,
    url:          "/dashboard",
    release:      "1.0.0"
  })
});

Both endpoints respond with 201 Created and the stored event object on success, or a 400/401 JSON error on failure.

FAQs

What does WatchTower do?

WatchTower helps developers a way to monitor their web apps. It helps teams see whether an app is reachable, review metrics, and get notified when the app is unreachable, allowing developers to respond to crashes quickly.

What data does the collector send to WatchTower?

The collector sends information about unhandled JavaScript exceptions, unhandled promise rejections, page load performance, DOM content loaded time, time to first byte, JavaScript memory usage, and the latency of fetch API requests.

Can I monitor more than one app?

Yes. Each registered app gets its own API key, so you can track multiple projects separately in WatchTower.

Does WatchTower affect my app's performance?

Not significantly. A small browser script reports errors and timing in the background without changing your server or build. Heavy work stays on WatchTower's side, so normal use should not slow your app down.

Can I use WatchTower during local development?

Yes. WatchTower can be used locally while running the server on http://localhost:3000. If your WatchTower instance is hosted elsewhere, open collector.js and modify baseUrl: 

const baseUrl = "https://your-watchtower-host.com";
