## Discussion

### What The Group Did Well

The Sprint 3 responses highlighted strong momentum, useful standups, and visible project progress.

Common strengths mentioned included:

- Running standups effectively as progress check-ins
- Helping different teams understand overall project progress
- Maintaining strong development speed and commitment
- Making clear progress toward the MVP
- Producing a polished demo and a strong project video
- Getting a working version of the app ready before code review
- Communicating well across the group

Several responses suggested that the team had matured in how it tracked progress, especially through standups that helped contributors maintain a broader understanding of the project.

### What Specific Teams Did Well

The thread described strong backend execution and effective frontend integration, especially after team restructuring.

Backend strengths mentioned in the thread included:

- Completing tasks efficiently without blocking one another
- Splitting issues cleanly so members could work independently
- Making steady progress through assigned work

Frontend strengths mentioned in the thread included:

- Integrating the UI/UX team effectively
- Delegating work well after the UI/UX and frontend teams merged
- Improving the dashboard
- Putting substantial effort into making the app look more professional
- Adapting quickly when features or designs needed to change

Overall, the responses indicate that both main teams handled task execution well, while the frontend side also absorbed structural team changes successfully.

### What Should Improve Next Sprint

The most common improvement themes were repo organization, cross-team collaboration, and clearer end-state planning.

Requested improvements included:

- Cleaning up and organizing the git repository
- Reducing confusion caused by many concurrent merges to `main`
- Improving inter-team communication
- Increasing collaboration between frontend and backend contributors
- Making the remaining project goals and current source of truth more explicit
- Clarifying what tasks are still left to finish
- Shifting focus toward polish, completion, and submission readiness

Several responses noted that the team had changed direction multiple times, which made it harder to tell what the final target and remaining priorities were at this stage of the project.

## Takeaways and Summary

This retrospective suggests Sprint 3 was successful in terms of visible product progress, but it also exposed the need for tighter coordination as the project approaches completion.

1. **Standups were a major strength this sprint:** multiple contributors highlighted them as useful progress checks and cross-team awareness tools.
2. **The project became more presentable:** the demo, video, and dashboard polish were all called out positively.
3. **Teams executed efficiently:** backend contributors emphasized independent task completion, while frontend contributors emphasized adaptation and integration.
4. **Team restructuring was handled well:** the UI/UX merge into frontend appears to have improved output rather than slowing progress.
5. **The next stage requires convergence:** repo cleanup, stronger collaboration, and a clearer shared definition of the final target are the main needs going into the next sprint.

**Key follow-up items:**

- Clean up the repo and improve merge hygiene
- Clarify the remaining task list and source of truth for final goals
- Improve collaboration between frontend and backend teams
- Focus the next sprint on project completion, polish, and submission readiness
