# Backlog

## User Stories

- As a developer, I want a documentation tab on the website so that I know how to set up the WatchTower in my software and answer any questions I have about how it works.
- As a user, I want to be able to change how my data is represented through different buttons that can switch between a bar chart, line graph, and table, and customize which charts and widgets appear on my dashboard, in order to better suit my preferences on how I like seeing data.
- As a developer, I want a widget with a log of different versions of my website and the uptime rate and number of bugs in order to assess which version of my app is most stable.
- As a developer, I want to use a performance metric app that does not slow down my own app, so that the performance errors I see are due to my app and not WatchTower slowing my app down.
- As a developer who values security, I want my data to be protected by my email and encrypted password, so that I can be worry free using WatchTower in my apps.
- As a developer, I want to make few changes to my existing code and just add a single collector file to my repo to collect performance and error data, so that my code stays clean and adding WatchTower is not a cumbersome process.
- As a developer, I want to receive notifications when the application experiences high error rates, downtime, or severe performance degradation so that I can quickly respond before they significantly impact users.
- As a developer, I want to monitor website uptime and service availability so that I can detect outages or inaccessible services and ensure the application remains operational for users.
- As a developer who wants to be able to clearly trace the origin of errors, I want metrics that capture the error origin in extreme detail, including the app version, timestamps, and page that the error is from.
- As a developer, I want to be able to monitor multiple projects and switch between them so that it is easy for me to simultaneously monitor those projects.
- As a user, I want a simple flow of the application, meaning I want a clear path to get my app's errors and not a lot of fluff, in order to get straight to my metrics and errors.
- As a developer, I want to see who pushed the changes that caused the error in order to better understand how to fix the error.
- As a user, I want to avoid false alarms from my website going down. I want the application to periodically check for downtime and, if the app is down for more than 3 checks, notify me, in order to minimize being notified when the website is experiencing infrequent downtime that resolves by itself.
- As a user, I want a simple dashboard with only a symbol telling me whether my site is down, has errors, or is up, with not a lot of clutter, in order to easily tell when my website is up.
